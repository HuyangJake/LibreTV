# 夸克网盘播放接入调研

日期：2026-10-24。基线：b261651。分支：feat/quark-drive。

## 结论

现有 NAS Docker + Next.js + Artplayer 架构可接入网盘播放，但尚未完成账号实测。用户提到的“猫 TV”可能指猫影视/CatVodOpen 或 TVBox 类客户端，具体产品未确认。这类方案由播放器、内容源/爬虫、网盘适配器组成；配置网盘账号不会自动产生影视目录。

## 外部依据

- https://github.com/jadehh/TVSpider ：上游 README 区分 CatVodOpen 与 TVBox 配置及运行时；目录记录包含夸克支持。不能由“都支持 JS”推断脚本互通。
- https://doc.oplist.org/guide/drivers/quark ：普通夸克驱动使用 Cookie，根目录 ID 为 0，目前要求本地代理；速度与会员、服务器带宽有关。Quark TV 驱动支持 302，但仅支持访问与下载。文档标明相关接口为逆向接口且维护受限，因此不能视作稳定官方 API。

上述页面已使用 ego-browser 阅读。未登录用户账号、未转存文件、未验证真实视频。

## 播放原理

自己的文件：账号授权 → 列目录 → 选择视频 → 获取带有效期的播放/下载地址 → 服务端代理或符合条件时直连 → 播放器。

分享资源：分享链接 → 提取码/分享凭证 → 列文件 → 视接口需要转存到自己的目录 → 获取地址 → 播放。具体转存流程尚需选定驱动并验证。转存、流量代理、视频转码是不同操作，转存不等于下载整个文件到 NAS。

## 现有实现与缺口

- src/lib/spider.ts、spider/worker.mjs：已有搜索、剧集、播放解析，但使用 XPTV 风格 search/getTracks/getPlayinfo 接口，不能直接执行任意 CatVod/TVBox JAR、Python 或 Node 模块。
- src/lib/spider-media.ts：已有服务端请求头保存、Range 转发、HLS 地址改写，可参考。
- src/lib/fetch-utils.ts：请求使用 AbortSignal.timeout；现有媒体入口传 20 秒，长媒体流需要独立审查响应体超时语义，不能直接认定可持续播放。
- docker-compose.nas.yml：已有持久卷和隔离 Spider 容器；Spider 明确不接收应用秘密。夸克凭证应保存在可信服务端适配层，不能注入远程脚本执行环境。
- 尚无网盘账号设置、目录浏览、网盘文件播放会话、凭证刷新及失效提示。
- 浏览器是否能播放取决于视频/音频编码和容器；代理不会解决所有 MKV、HEVC、DTS 等兼容问题。转码需要单独评估 NAS 硬件与资源。

## 建议实现顺序

1. 先实现单账号、只读“我的夸克网盘”，目录浏览和单文件播放；保留现有影视源。
2. 将 provider 接口与播放器解耦：listFiles、resolvePlayback、检查授权状态。账号秘密只留服务端，不在 URL、日志或源配置导出中返回。
3. 网盘媒体代理通过不透明播放会话绑定文件及上游主机，限制重定向与私网地址，防止带凭证的代理被用来访问任意 URL；支持 Range/206、拖动进度、取消、过期刷新和长流。
4. 可先验证 NAS 上的 OpenList 挂载，再接入其目录/下载能力；这是减少自维护逆向接口的候选方案，仍需核对接口及授权隔离，不能保证驱动长期可用。
5. 自有文件链路验证后，再接入分享链接、按需转存和明确的临时目录管理。自动搜索资源属于另一个内容源功能。

## 验证门槛

- 正常目录、无效/过期授权、空目录及分页。
- 可播放的 MP4/HLS、拖动、连续播放超过 20 秒、断开取消、地址过期。
- Cookie 不出现在客户端响应或日志，媒体会话不可用于任意主机请求。
- 局域网与外网分别验证；NAS 中转外网播放受家庭上行限制。
- 真正端到端验收需要用户账号授权和一个可访问测试视频。当前结论为架构可行，非已经接通。
