# 猫影视与夸克实现及验证记录

更新：2026-10-25。独立 worktree `LibreTV-quark`，分支 `feat/quark-drive`，基线 `b261651`。当前测试 Runtime 为兼容补丁6，专用夸克账号授权有效。本功能改动均留在独立worktree，未写入原 `LibreTV` / `nas` 工作区，未替换正式 NAS 服务，未配置公网入口。按用户最新要求，本轮先验收局域网。

## 已确认范围

兼容用户提供的固定猫影视源包，提供统一搜索、按源片库、线路/剧集选择和夸克播放。一个专用测试账号由所有观看者共用，仅管理员管理授权和源包。允许按需自动转存至本实例创建的专用目录；清理由管理员手动触发，只处理有归属记录且仍位于专用目录的文件。目标为内外网两路1080p，4K可选；手动选择线路和画质，不在NAS做转码。源包手动更新与回退，先独立测试。

## 实现

- `catvod/`：独立Node 22容器，非root、只读根文件系统、丢弃Linux capabilities、限制内存/CPU/进程数。监督进程持有内部令牌，源包子进程不获得应用密码或内部令牌，日志出口关闭。
- `test-source.json` 固定原始MD5/SHA-256。入口为用户给定的 `index.js.md5`；先校验后打补丁。未知上游版本拒绝激活，其他任意JS不能在此运行。
- `compatibility.mjs` 禁用可变启动配置、远程关闭开关、自动清理、日常转存维护和聊天消息加速；限制429重试；修复详情授权初始化、缓存清空及无转码结果时的原画回退。
- 目录递归保留完整路径和分页上下文，每个真实目录独立成为线路，字幕只在本目录匹配。`quark-directory-patches.json` 的7个位置均与固定原包唯一匹配。
- `quark-ledger.cjs` 在转存前记录意图、跟踪异步任务及保存后的fid。用稳定账号标识、分享ID、原始fid和目标目录标识去重；重启后先远程核对文件归属再复用，未完成任务保留记录。
- 所有源包直接删除和聊天请求均被拒绝。可信清理接口使用 `file/sort` 分页，只查询已记录的专用目录，核对fid及父目录后才删除；不使用会忽略fids参数的GET `/file`。
- 回退恢复源包和配置，保留当前夸克授权与完整归属账本。回退不能撤销远程文件操作，也不能恢复已经删除的测试文件。
- 补丁6处理分享凭证和文件转存凭证的独立过期：每次解析夸克播放前重新列出分享，按分享ID和文件fid更新整条播放信息，不能用同名集数匹配。目录/转存接口遇到明确41016时只刷新重试一次；分享被取消或封禁不重试。转存被41012/41016/41020/41031明确拒绝且没有任务时解除该意图；网络异常和未知结果仍保留记录待核对。
- `src/lib/catvod*.ts` 适配搜索、分类和详情，播放地址使用服务端不透明会话。用户点击播放才转存和解析；质量探测不会触发转存。
- MP4原生播放和HLS分别按真实Content-Type选择，不能仅凭“高清”等标签判断。支持Range/206、HLS音轨/字幕/密钥/初始化段/分片改写；长视频没有总响应体超时。
- 凭证只保留在服务端。跨域跳转默认移除凭证；只有受控夸克代理跳至HTTPS默认端口的夸克CDN时保留其Cookie。相似域名、非标准端口及其他域名不获得Cookie。
- 独立 `ADMIN_PASSWORD` 与观看密码不同，管理员会话30分钟。普通观看用户可使用“打开夸克分享”，看不到账号与源包管理控件。首版只支持无需提取码的标准视频分享。
- 观看进度按线路/目录和集数隔离，历史保留线路及分享源地址。观看进度心跳和媒体请求租约共同阻止播放中清理；停止播放两分钟后才允许维护。CatVod播放不使用旧播放器暂停后整集预取功能。

## 独立部署与当前运行

可用 `docker-compose.catvod-test.yml` 单独部署，分别设置观看密码、独立管理员密码及至少24字符内部令牌：

```sh
docker compose --env-file .env.catvod-test.local -p libretv-catvod-test -f docker-compose.catvod-test.yml up -d --build
```

Compose默认只绑定 `127.0.0.1:18081`。本机被忽略的 `.env.catvod-test.local` 已设置 `CATVOD_TEST_BIND=0.0.0.0`，按用户要求开放局域网。管理员在设置→源管理→猫影视与夸克中加载固定源、选择站点并扫码。控制与源包端口不对外发布；当前不配置外网入口。

本轮实际采用宿主机生产构建加独立Runtime容器：应用监听 `0.0.0.0:18081`，当前Wi-Fi地址为 `192.168.1.130`；控制18790、源包19989仍仅本机绑定。应用可用 `npm run start:catvod-test` 重新启动，运行期间需保持该进程和电脑网络在线；未安装系统自启动服务。IP由局域网分配，改变后应使用新地址。Runtime持久卷为 `libretv-catvod-test-runtime`。Compose创建的卷与本轮手工测试卷不同，迁移前需明确保留授权和数据，勿删除数据卷。原NAS未部署变更。
